# NUC-008 — Persistir e recuperar acervo

Tipo: back-end local. Componentes v1.0: UC-008, UC-009; suporte UC-001/002/006/007; DATA-007, DATA-008; repositórios dos demais donos; API-007, API-008, MSG-004. Dependências: Nenhum núcleo síncrono; portas de dados dos domínios. Critérios herdados sem redefinição: AC-008, AC-009. Documentos canônicos em 03_Artefatos; nenhum componente aprovado pelo humano é alegado.

Contrato observável: Transação confirma mudanças; restore troca snapshot validado e preserva anterior até sucesso. Ator: leitor local/evento do comando; permissões herdadas dos serviços. Entrada sempre inclui obra/revisão ou jobId e, nas mutações, commandId. Saída é resultado tipado/estado real; erro nunca vira confirmação visual de sucesso.

Cenário adverso: negar token/obra removida → erro e retorno à seleção/acervo; injetar repetição → mesmo efeito lógico; falha de cálculo → manter último layout; falha de escrita → preservar rascunho e estado não salvo; cancelamento → nenhuma troca de geração não confirmada. São inspeções de especificação, não testes executados.

Riscos: perda de continuidade e feedback antecipado. Controles: revisão imutável, âncora lógica, confirmação após commit, consulta autoritativa caso evento se perca. Acessibilidade dos núcleos interativos: foco/teclado/estado anunciado nos contratos VIEW. Dispensável nas rotinas headless como UI própria, mas não no consumidor do resultado.
